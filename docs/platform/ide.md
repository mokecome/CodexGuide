# IDE

IDE 入口適合貼近編輯器上下文的高頻小任務。它的優勢是檔案、選區、符號跳轉、錯誤資訊和開發者當前注意力都在同一個環境裡。

## IDE 適合什麼

- 解釋當前檔案或選中程式碼。
- 為一個函式補測試。
- 區域性重構。
- 生成註釋、文件或型別說明。
- 審查當前 diff。
- 快速理解錯誤資訊和呼叫鏈。

## 選區任務寫法

選區越準確，結果越穩定。推薦模板：

```text
請只基於當前選中的程式碼解釋：
1. 它在模組中的職責
2. 輸入輸出和副作用
3. 可能的邊界情況
4. 如果要補測試，建議覆蓋哪些場景
```

如果允許修改：

```text
請只修改當前檔案和對應測試檔案。

目標：為當前函式補充邊界測試。
要求：
1. 先解釋測試場景。
2. 修改後執行相關測試。
3. 不做無關重構。
```

## IDE 中的高頻任務

| 任務 | 推薦輸入 | 結果檢查 |
| --- | --- | --- |
| 解釋程式碼 | 選中函式或類 | 看是否說清職責和邊界 |
| 補測試 | 選中函式和現有測試 | 看測試是否能失敗後透過 |
| 修型別錯誤 | 貼上錯誤資訊和檔案 | 看是否影響執行時行為 |
| 區域性重構 | 指定檔案和目標 | 看 diff 是否可讀、測試是否透過 |
| 寫文件 | 選中 API 或設定 | 看示例是否可執行 |
| Review diff | 提供當前 diff | 看是否優先發現行為風險 |

## 和 CLI 的配合

IDE 適合區域性上下文，CLI 適合完整驗證。建議流程：

1. 在 IDE 中解釋或修改當前檔案。
2. 回到 CLI 執行相關測試。
3. 用 `git diff` 檢查最終變更。
4. 需要更大上下文時，讓 CLI 讀取倉庫規則和測試設定。

## 注意事項

- 不要用過大的選區開始任務。
- 區域性任務寫清“只改當前檔案”或“只改對應測試”。
- 重要改動仍要跑測試。
- 生成註釋時避免重複程式碼含義，優先解釋邊界、原因和約束。
- 涉及敏感設定時不要把 token 或 `.env` 直接貼入對話。
