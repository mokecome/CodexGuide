# 實踐方法

Codex 的學習重點不只在命令和介面。更關鍵的是把任務設計、上下文管理、安全邊界和驗證閉環訓練成習慣。

## 三條底線

- 任務要可驗證：沒有驗證方式的任務，很難判斷結果品質。
- 範圍要可控制：越靠近核心業務、權限、支付、資料，越需要小步推進。
- 結果要可覆盤：每次任務都要留下“原因、改動、驗證、風險”。

## 最小閉環模板

```text
請處理：[明確目標]

背景：
- [當前現象/業務上下文]

範圍：
- 可以修改：[檔案/目錄]
- 保持不變：[檔案/目錄/行為]

約束：
- 不引入新依賴
- 保持公開 API 相容
- 不處理生產資料或敏感憑據

驗證：
- 執行：[命令]
- 如果失敗，請定位原因並說明阻塞

交付：
- 改了什麼
- 為什麼這樣改
- 驗證結果
- 剩餘風險
```
