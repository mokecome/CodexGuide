# 非開發工作流

Codex 的價值不只體現在寫程式碼。只要任務涉及一組檔案、明確目標和可複核結果，Codex 就能提供幫助。

## 文件工作

適合任務：

- 把 README 改成新手友好的版本。
- 根據程式碼生成模組說明。
- 整理遷移指南。
- 生成釋出說明。
- 把 issue、PR、commit 整理成周報。

任務模板：

```text
請閱讀當前倉庫的 README、docs 和 package 設定，幫我整理一份新手上手指南。

要求：
1. 不修改程式碼。
2. 命令必須來自倉庫真實設定。
3. 不確定的步驟標註為“待確認”。
4. 輸出目錄結構、安裝步驟、開發命令、測試命令和常見問題。
```

## 學習工作

適合任務：

- 讓 Codex 按學習順序解釋程式碼庫。
- 生成“從入口到核心模組”的閱讀路線。
- 把複雜模組講成產品、設計或運營也能理解的語言。
- 把陌生技術棧拆成學習清單。

任務模板：

```text
請把這個倉庫當成學習材料。請按初學者閱讀順序講解：
1. 先看哪些檔案
2. 每個目錄承擔什麼職責
3. 關鍵資料流或呼叫鏈
4. 學完後可以做的 3 個練習
```

## 產品與運營工作

適合任務：

- 把 PR 改動翻譯成使用者影響。
- 生成釋出公告草稿。
- 檢查文案和功能說明是否一致。
- 從 issue 中提取使用者痛點。

任務模板：

```text
請閱讀當前 diff，把技術改動整理成產品釋出說明。請包含：
1. 使用者能感知到的變化
2. 管理後臺或設定變化
3. 可能影響舊使用者的地方
4. 需要客服或運營同步的話術
```

## 知識管理

Codex 很適合把零散經驗沉澱成模板：

- 排障記錄。
- FAQ。
- 任務模板。
- 團隊規範。
- 案例覆盤。

最終目標是把“每次臨時問一次”變成“下一次直接複用”。
