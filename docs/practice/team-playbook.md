# 團隊實踐

團隊使用 Codex 的關鍵是把規則寫清楚、把驗證跑起來、把案例沉澱下來。

![Codex 安全邊界分層](/images/codex-safety-layers.svg)

## 團隊接入清單

| 專案 | 建議 |
| --- | --- |
| `AGENTS.md` | 寫清專案結構、命令、風格、安全邊界 |
| 測試命令 | 提供最小相關測試和全量測試命令 |
| PR 模板 | 要求說明 Codex 參與範圍、驗證結果和風險 |
| 安全規則 | 明確生產資料、金鑰、釋出、遷移的審核要求 |
| 案例庫 | 把成功任務和失敗覆盤都沉澱下來 |

## 團隊版 `AGENTS.md` 提綱

```markdown
# AGENTS.md

## 專案概覽

## 常用命令

## 目錄邊界

## 程式碼規範

## 測試要求

## 安全邊界

## PR 交付要求
```

## PR 描述模板

```markdown
## 背景

## 改動

## Codex 參與範圍

## 驗證

## 風險

## 截圖或日誌
```

## 例會覆盤問題

- 哪類任務 Codex 表現穩定？
- 哪類任務容易失控或需要更強約束？
- 哪些命令、規則、截圖說明應該寫入 `AGENTS.md`？
- 哪些成功案例可以沉澱成模板？
- 哪些失敗案例應該寫入排障手冊？
