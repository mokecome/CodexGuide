# Codex × Google Workspace：整理團隊資料

台灣團隊常見的協作工具通常是 Google Drive、Google Docs、Google Sheets、Notion、Slack、LINE 或 GitHub。這類資料不一定需要一開始就接 API；新手更適合先用「匯出資料、讓 Codex 盤點、再人工確認」的方式。

## 適合處理什麼

| 場景 | 可以交給 Codex 的任務 | 人工要確認 |
| --- | --- | --- |
| Google Docs | 摘要長文、整理 SOP、拆成任務清單 | 是否有遺漏決策 |
| Google Sheets | 分類欄位、找缺漏資料、產生報告大綱 | 數字與公式是否正確 |
| Notion | 整理資料庫、建立知識卡片、補齊標籤 | 權限與發布範圍 |
| Slack / LINE 匯出文字 | 轉成會議紀要、待辦、風險清單 | 私人資訊是否需要遮蔽 |

## 新手安全做法

不要一開始就讓 Codex 直接寫回雲端工具。先把資料匯出成 Markdown、CSV、PDF 或文字檔，放在一個測試資料夾，請 Codex 只讀取和整理。

範例提示詞：

```text
請先閱讀這個資料夾裡的 Google Docs 匯出檔和會議紀錄。
不要修改原檔。
請輸出：
1. 這批資料在講什麼
2. 重要決策
3. 待辦事項
4. 風險與待確認問題
5. 建議整理成哪些 Notion 頁面
```

## Google Sheets / CSV 範例

把試算表下載成 CSV 後，可以這樣問：

```text
請分析這份 CSV。
先不要改檔案。
請列出欄位用途、缺漏值、異常資料、可分群方式，最後產生一份適合主管看的 1 頁摘要。
```

如果要讓 Codex 寫回新檔，先要求它另存新檔，不要覆蓋原始資料：

```text
請根據分析結果建立一份新的 cleaned-report.csv。
不要覆蓋原始 CSV。
完成後請說明你新增、刪除或修正了哪些欄位。
```

## 需要接 API 時

等流程穩定後，再考慮接 Google Drive、Notion、Slack 或 GitHub 的 MCP / API。接 API 前先寫清楚三件事：

- Codex 可以讀哪些資料夾或資料庫。
- Codex 不能讀哪些私人資料、客戶資料或金鑰。
- Codex 是否允許寫回，還是只能產生草稿。

## 驗收標準

任務完成後，不只看它有沒有輸出文字，還要檢查：

- 是否保留原始資料來源。
- 是否把事實、推論、建議分開。
- 是否列出待人工確認的項目。
- 是否沒有暴露密碼、Token、客戶個資或內部機密。

這個案例的重點不是「接越多工具越好」，而是先讓 Codex 學會整理、盤點、分類和產生可驗收的草稿。
